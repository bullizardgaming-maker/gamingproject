## B. Values to paste — staging (`render.yaml`)

Render asks for these on **New → Blueprint → `render.yaml`**:

| Key | Value | How |
|---|---|---|
| `DATA_ENCRYPTION_KEYS` | `v1:<32 random bytes, base64>` | `echo "v1:$(openssl rand -base64 32)"` — keep a copy offline (password manager). Data encrypted with it is unreadable without it. |
| `PUBLIC_WEB_URL` | `https://staging.<domain>` | exact origin, no trailing slash |
| `PUBLIC_API_URL` | `https://api-staging.<domain>` | exact origin, no trailing slash |
| `DATABASE_URL` | Neon `staging` branch, **pooled** connection string, with `?sslmode=require` | Neon → Branches → staging → Connection string → "Pooled" |

Generated by Render (nothing to paste): `JWT_SECRET`, `FINGERPRINT_KEY`, `CRYPTO_INDEXER_SECRET`, `REDIS_URL`, `CLAMD_HOST`.

Vercel, environment `staging` (Settings → Environment Variables, scope: staging / the `staging` branch):

| Key | Value |
|---|---|
| `VITE_DEMO` | `false` |
| `VITE_API_URL` | `https://api-staging.<domain>` |

Custom domains: Render API service → Settings → Custom Domains → `api-staging.<domain>`; Vercel project → Domains →
`staging.<domain>` assigned to the staging environment/branch. Add the DNS records each dashboard shows.

Optional on staging: `SENTRY_DSN`; for the NOWPayments underpayment test set `PAYMENT_PROVIDER=nowpayments`,
`SANDBOX_MODE=false`, `NOWPAYMENTS_API_KEY`, `NOWPAYMENTS_IPN_SECRET`, `NOWPAYMENTS_EMAIL`, `NOWPAYMENTS_PASSWORD`,
`NOWPAYMENTS_2FA_SECRET` (sandbox values) on the staging env group and set the IPN URL in the NOWPayments sandbox to
`https://api-staging.<domain>/v1/payments/webhook/nowpayments`.

## D. Deploy steps (staging), in order

1. Render → **New → Blueprint** → this repository → `render.yaml` → paste the four values in B → Apply. Render builds
   the API image, runs `node dist/migrate.js` before the first start (all migrations through 068), and starts the API
   with the worker in-process, Redis and ClamAV on the private network.
2. Add the custom domain `api-staging.<domain>` to the API service; wait for the certificate.
3. Vercel: set the two staging variables; assign `staging.<domain>`; redeploy the staging environment.
4. Check: `curl https://api-staging.<domain>/readyz` → `{"ok":true}`; open `https://staging.<domain>` → the real app (no
   "Preview with sample data" bar).
5. Staff accounts: sign up in the app with your real email, then API service → **Shell** →
   `node dist/scripts/make-staff.js --email <you> --role admin` (roles: arbiter, support, lead, finance, compliance,
   admin). Every staff account turns on 2FA at once (Account → Two-factor). Sample catalogue (optional): `node dist/seed.js`.
6. Money paths: GitHub → Actions → **staging money paths** → Run workflow (setup: `docs/STAGING.md` §5)
   → every line `PASS` (underpay `skipped` until the NOWPayments sandbox is set).
7. Kill switches: Actions → **staging kill switches** (or by hand: Ops → Controls → pause each switch, confirm the banner
   and the 503, resume). Load: Actions → **staging load test**. Alerts: Ops → Controls
   thresholds; the `ops_alerts` job runs every 15 minutes and emails admins + finance (on staging emails go to the log).
8. Security scan: Actions → **staging ZAP scan** (`security/zap/README.md`). Fix every High, re-run.
9. Backup drill (gate §4): Neon → Branches → "Restore" the staging branch to a point in time an hour back, confirm the
   app still answers; note the date in the launch gate's Results table.
